# My Personal AI Usage Rules

## Rule 1 - What I will never paste
- Secrets, tokens, passwords, API keys, `.env` contents, or production configuration.
- Real customer, user, company, school, or personal data.
- Private code I am not authorized to share.
- Full logs or stack traces before checking that they do not include secrets, private paths, or real data.

## Rule 2 - What I will always verify before accepting
- I will read generated code line by line before accepting it.
- I will compare AI suggestions against the project files, tests, and documented scope.
- I will run the relevant tests or clearly record when I did not run them.
- I will verify security findings with file evidence before treating them as valid.
- I will check that generated changes do not add unrelated features, dependencies, or behavior.

## Rule 3 - How I will record AI contributions
- I will keep AI-assisted decisions in the project docs when they affect design, security, or governance.
- I will record which files were inspected, which tests were run, and what limits or assumptions remained.
- I will label AI findings as draft until I confirm them against the code.
- I will keep prompts and review notes focused on the specific task so the project history stays understandable.
